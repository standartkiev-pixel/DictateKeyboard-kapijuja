2. WHY THE FORK EXISTS
======================

The original Dictate keyboard has a strong full-keyboard + voice/AI architecture, but this fork
must be independently usable and maintainable.

Goals:
- remove dependence on Dictate Cloud/payment infrastructure;
- remove Google Play Billing wiring belonging to that product;
- keep BYOK/direct provider access;
- keep custom/self-hosted providers;
- keep on-device STT;
- make voice dictation robust against network loss;
- never casually destroy long recorded speech;
- make retained recordings easy to find and reuse;
- allow the same saved audio to be re-recognized by another AI;
- remain independently brandable, buildable, signable and releasable.

9. ORIGINAL USER-FACING FAILURE THAT DROVE THIS WORK
====================================================

Observed problem:
after a network drop/provider failure, the keyboard could remain in "Transcribing…" for many minutes
or appear effectively stuck.

Important root causes discovered:
- OpenAI-compatible OkHttp request timeout around 120 s;
- old executeForBody default allowed initial request + up to 3 retries;
- in the worst case that could turn into many minutes of waiting;
- ambiguous retries of billable/non-idempotent STT POSTs could re-upload/re-charge;
- different provider types had different lifecycles:
  ordinary HTTP;
  Soniox/AssemblyAI async polling;
  realtime WebSocket;
  local sherpa-onnx;
  long-form segmented parallel jobs.

The solution was intentionally placed at the controller/state-machine level rather than adding
provider-specific hacks.


10. SAFE RECORDING CANCEL UX
============================

User requirement:
a long recording must NEVER be destroyed by one nervous/accidental tap.

Normal Smartbar:
- first tap on Cancel/Trash is NON-DESTRUCTIVE;
- recording continues;
- in-keyboard confirmation appears for 5 seconds;
- microphone/continue action leaves the recording intact;
- explicit red delete action really discards;
- if the user does nothing, confirmation disappears and recording continues.

Legacy layout:
- space is tighter;
- first tap only arms deletion;
- second tap within 5 seconds confirms deletion.

Why no ordinary Material modal/dropdown:
focusable popup UI inside an IME can steal editor focus and hide the keyboard.

RecordingController writes microphone PCM continuously to disk while speech is being captured.
The audio is not merely kept in RAM waiting for Stop.


11. UNIQUE RECORDING FILE OWNERSHIP — CRITICAL RACE FIX
=======================================================

The old recorder reused:
cache/dictate_audio.wav

That was unsafe in this scenario:
1. old transcription is cancelled;
2. user immediately begins another recording;
3. old native/local job returns late;
4. old cleanup deletes a pathname now reused by the NEW recording.

Fix:
- every RecordingController session/segment now writes to a unique cache WAV;
- filenames are never reused across sessions;
- request-scoped temp files are also unique.

Unique/request-scoped ownership now applies to:
- microphone WAVs
- long-form segments
- history replay temp files
- imported-audio handoff files
- trimmed audio
- speed-up copies
- packed m4a upload copies
- long-form merged rescue files

Batch requests also use a generation ownership token.
A late cancelled native/local job may clear only its own state/files; it cannot:
- clear a newer inFlightAudio pointer;
- cancel a newer watchdog;
- delete a newer request's cache file.

DO NOT reintroduce fixed request temp names such as dictate_audio.wav.


12. STOP DURING "TRANSCRIBING…" — RECOVERABLE, NOT DESTRUCTIVE
==============================================================

Kapijuja intentionally differs from old upstream behavior.

Old behavior:
Stop cancelled the request and the request cleanup deleted the audio.

Current behavior:
- explicit Stop is visible in the Transcribing Smartbar;
- Stop first makes a private rescue copy;
- then cancels the provider coroutine / OkHttp Call;
- audio remains available for Send again;
- explicit discard remains a separate action;
- imported MP3/Ogg/etc preserve their real container extension;
- local STT is also stoppable/recoverable.

The cancellation path is centralized.
Do not create another provider-specific "stop" mechanism.

14. PROCESS-DEATH RECOVERY
==========================

Manual Stop or watchdog rescue is not only transient cache state.

When History is enabled:
- stopped/stalled audio is also force-archived as a recoverable History entry;
- it survives the transient resend chip disappearing or the IME process being killed.

Privacy rules:
- never archive password/incognito sensitive dictation fields;
- do not duplicate an existing History replay into another failed/stopped row;
- History remains subject to user deletion/pruning controls.


15. CROSS-PROVIDER RE-RECOGNITION
=================================

A retained recording can be sent to another recognizer directly from the in-keyboard History panel.

UI:
- History stays inside the IME;
- the replay action opens an in-keyboard recognizer chooser;
- do NOT replace it with a focusable Material DropdownMenu.

The chooser can show configured transcription-capable providers such as:
- OpenAI
- Groq
- Gemini
- Deepgram
- other built-ins
- custom/self-hosted endpoint
- installed on-device model

Unconfigured providers may be visible but disabled so the architecture is discoverable.

ONE-SHOT PROVIDER OVERRIDE:
choosing Groq for one saved clip must NOT change the user's normal global transcription provider.

After successful replay:
- transcript text is replaced with the new result;
- provider/model/language metadata is updated to describe the recognizer that actually produced it.

Potential future enhancement:
"recognition variants" linked to ONE physical audio asset, allowing OpenAI/Groq/Gemini results
side-by-side without duplicating WAV files. This is NOT implemented yet.


16. PROVIDER-INDEPENDENT NO-PROGRESS WATCHDOG
=============================================

Implemented in DictateController.

The watchdog does NOT use a simplistic total-duration timeout.
It watches meaningful forward progress.

The existing Settings -> AI providers -> Network -> Request timeout setting is reused as the
no-progress budget:
- range 30–600 s
- default 120 s

Meaning:
"How long can NOTHING meaningful happen before I want my recording back?"

Progress heartbeat sources:
- multipart/raw/base64 upload bytes;
- successful Soniox async status polls;
- successful AssemblyAI async status polls;
- local sherpa-onnx decode/segmentation steps;
- long-form segment provider/local progress.

On watchdog timeout:
- do NOT set UiState directly;
- route through the SAME safe retained-audio cancel path as manual Stop;
- underlying coroutine/OkHttp work is cancelled;
- audio is preserved;
- UI shows a recoverable "No progress · recording kept" state;
- Send again remains available;
- History archive is created when allowed.

This shared terminal path is an important invariant.


17. RETRY POLICY
================

Old generic executeForBody default could allow 3 application retries after the initial attempt.

Current STT policy:
- ordinary transcription network calls: initial attempt + at most ONE application-level retry;
- OpenRouter transcription: ZERO application-level retries;
- safe async status GET polls keep their explicit retry budget.

Reason:
audio upload/job-creation POSTs are billable and effectively non-idempotent.
After an ambiguous timeout, the client cannot know whether the provider already received/charged
the request.

OkHttp may still retry failures it can prove safe at the transport layer.

Long-form used to add another outer retry on top of provider retry.
That retry multiplication was removed.

Network tests now cover:
- transcription heartbeat emission;
- one-retry ceiling;
- existing OpenRouter zero-retry behavior.


18. REALTIME PATH
=================

Realtime has a separate existing finalization mechanism:
- finish the stream;
- wait briefly for final provider words;
- approximately 1.2 s finalize watchdog;
- cancel socket;
- if realtime failed or transcript is empty, fall back to batch transcription of the retained WAV.

Do not wrap realtime with another competing socket watchdog.
Its batch fallback is already protected by the common no-progress watchdog.


19. LONG-FORM SEGMENTED DICTATION
=================================

Long-form is special because multiple segment jobs may exist simultaneously.

Safety work completed:
- every cut segment WAV remains cache-owned until the session reaches a terminal state;
- this temporary ownership exists even if permanent History audio retention is OFF;
- permanent History preference still controls successful long-term retention;
- final drain starts the common no-progress watchdog;
- segment upload/poll/local-decode activity refreshes heartbeat;
- Stop/watchdog cancels ALL tracked segment jobs as one operation;
- active recorder tail is finalized if necessary;
- retained segment WAVs are concatenated in speaking order into one rescue WAV;
- provisional partial text is cleared before a future resend;
- late cancelled segment results are blocked from re-appearing;
- old outer retry multiplication was removed.

Important privacy distinction:
temporary cache ownership for recovery is NOT the same as permanent History retention.


20. LOCAL STT
=============

LocalTranscriptionProvider uses sherpa-onnx.

Progress heartbeat was added to:
- initial decode-to-mono work;
- streaming chunk processing;
- offline decode boundaries;
- VAD/segmented long-audio processing.

This prevents a slow-but-alive local model from being mistaken for a dead request.

Caution:
some native decode calls cannot be instantaneously interrupted internally.
Generation ownership is therefore necessary so a late return cannot corrupt a newer request.


21. AUDIO IMPORT
================

Picked/shared audio has separate import machinery with visible progress.

Import remains more generous than keyboard dictation because large media may legitimately take longer.

Import temp handoff filenames are now unique to avoid cross-request cleanup races.

Do not force the ordinary short-dictation timeout assumptions onto large imported files.

24. USER-INTERFACE PRINCIPLES FOR THIS FORK
==========================================

The owner strongly values "cannot accidentally lose work" behavior.

Rules:
- destructive actions require meaningful confirmation;
- while confirming recording deletion, capture should continue when technically safe;
- Stop of network work should not imply Delete of recorded speech;
- recovery actions should be close to where the problem happened;
- History should remain near Clipboard, not buried several settings screens away;
- avoid focusable popup UI that can hide the IME;
- visible provider choice should not silently mutate unrelated global settings;
- never make a user re-speak a long recording just because the network failed;
- prefer one physical audio file with metadata/variants rather than unnecessary duplication.

When uncertain, optimize for recoverability and explicit user intent.

26. DO-NOT-BREAK INVARIANTS
===========================

1. One accidental tap must not destroy a long recording.
2. Manual Stop during Transcribing must preserve audio.
3. Watchdog timeout must reuse the same recovery path as manual Stop.
4. CancellationException must propagate; never turn cancellation into a retry.
5. Old native/local jobs may not touch newer request state/files.
6. Request-scoped temp filenames must remain unique.
7. Generic billable STT POST must not return to 3 retries.
8. OpenRouter STT must remain zero application retries.
9. Async status GET retries must not be confused with billable re-upload retries.
10. History replay provider choice must remain one-shot, not mutate global provider preference.
11. Sensitive password/incognito dictation must never be archived.
12. Long-form segment audio must remain recoverable until terminal cleanup.
13. Realtime fallback must retain its WAV and enter protected batch flow.
14. Dictate Cloud/Billing must not be reintroduced.
15. Upstream licenses/attribution must remain.

Test manual Stop:
1. record 20–60 s;
2. send;
3. while Transcribing, press Stop;
4. network/provider work ends;
5. audio is preserved;

7. History contains a recoverable recording when enabled;
8. resend succeeds.

Test network loss:
1. record;
2. send;
3. disable Wi-Fi/mobile data during upload/wait;
4. verify no endless Transcribing;
5. verify watchdog eventually terminates at configured no-progress budget;
6. audio survives;
7. resend after restoring network succeeds.

Test provider switch:
1. preserve a recording in History;
2. replay once with provider A;
3. replay same physical audio with provider B;
4. confirm global provider remains unchanged;
5. confirm row metadata reflects the provider that produced the current text.

Test accidental cancel:
1. speak for a long time;
2. tap recording Trash once;
3. verify microphone continues;
4. wait >5 s;
5. verify recording still exists/continues;
6. repeat and explicitly confirm delete.

Test rapid Stop -> new recording:
1. stop a local/native transcription;
2. immediately begin another recording;
3. ensure old cleanup cannot delete/corrupt the new WAV or cancel its watchdog.

Test long-form:
1. create multiple segments;
2. stop while final segment jobs are still in flight;
3. verify all jobs stop;
4. verify one merged rescue WAV is available;
5. resend it;
6. verify no late old segment text reappears.

Test process death:
1. stop/watchdog a transcription;
2. force-stop/kill IME/app process before using resend chip;
3. reopen;
4. verify recoverable History copy remains.
